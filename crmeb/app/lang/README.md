# 多言語（中国語 / English / 日本語）

CRMEB の多言語は **2 系統** で動いています。両方を揃えないと片方だけ中国語のままになります。

| 系統 | 実体 | 使われる場所 |
| --- | --- | --- |
| PHP 言語ファイル | `crmeb/app/lang/{zh_cn,en_us,ja_jp}.php` | ThinkPHP の `lang()` ヘルパー |
| DB 言語パック | `eb_lang_type` / `eb_lang_code` / `eb_lang_country` | API のレスポンスメッセージ、uni-app（H5 / ミニプログラム / APP）の全 UI 文言 |

実行時の翻訳は `crmeb/app/common.php` の翻訳ヘルパーが担当し、
**中国語の原文 → `eb_lang_code.code` → 対象言語の `lang_explain`** という順に引きます。
言語の判定はリクエストヘッダー `Cb-lang` →（無ければ）`eb_lang_type.is_default` →（無ければ）`Accept-Language` の順です。

## 収録言語

| type_id | language_name | file_name | 状態 |
| --- | --- | --- | --- |
| 1 | 中文 | `zh-CN` | 有効（既定） |
| 2 | English | `en-US` | 有効 |
| 6 | 日本語 | `ja-JP` | 有効 |
| 3,4,5,7〜10 | 繁體中文 / Français / Italiano / 한국어 / Монгол / ภาษาไทย / ViệtName | — | `status=0`（データは残置。管理画面から再有効化可能） |

## 適用手順

### 新規インストールの場合

`crmeb/public/install/crmeb.sql`（インストーラ本体）に反映済みです。追加作業はありません。

### 既存環境の場合

```bash
mysql -u<user> -p <database> < crmeb/public/install/lang_zh_en_ja.sql
```

パッチの内容は 4 つです。

1. `eb_lang_type` … 中国語 / English / 日本語 のみ `status=1`
2. `eb_lang_country` … `ja` / `en` / `en-GB` などの変種コードを対応する言語へ割当
   （既定データは `zh-CN` / `en-US` / `ja-JP` の完全一致のみで、`navigator.language`
   が `ja` を返す環境では中国語にフォールバックしていました）
3. 言語パックの欠落コードを補完（`NOT EXISTS` ガード付きなので再実行しても安全）
4. 日本語訳の補正 482 件

テーブル接頭辞が `eb_` 以外の場合は一括置換してください。
`INSERT` はすべて `NOT EXISTS` ガード付き、`UPDATE` は固定値の代入なので、**再実行しても結果は変わりません**。

### 2. キャッシュクリア

翻訳テーブルは `CacheService` に 1 時間キャッシュされます。適用後は管理画面の
「システム設定 → キャッシュクリア」を実行するか、`crmeb/runtime/cache` を削除してください。
uni-app 側は `eb_lang_code` の更新で lang version が上がると自動で取り直します。

### 3. 既定言語の変更（任意）

- 管理画面: 設定 → 多言語設定 で既定言語を切り替え
- または `crmeb/.env` の `[LANG] default_lang`（`zh-cn` / `en-us` / `ja-jp`）

## 日本語訳の品質について

`ja_jp.php` の訳語は `eb_lang_code`(type_id=6) と **1 文字も違わないよう生成**しています。
同じ中国語原文が PHP 経由でも API 経由でも同じ日本語で出るようにするためです。

ベースは CRMEB 同梱の機械翻訳で、そのうち **482 件**を補正済みです。

- **空白の除去（365 件）** … 機械翻訳が挿入する日本語中の半角スペースを除去。
  `パラメータ エラー`→**パラメータエラー**、`サービス スコアは 1 ～ 5 の整数`→**サービススコアは1～5の整数**、
  `{:num} を超える`→**{:num}を超える**。ラテン文字まわりの空白（`access_token 取得時`）は
  日本語組版として正しいので残しています。
- **トースト文言の統一** … 保存しました / 削除しました / 変更しました など「〜しました」形へ
- **明らかな誤訳** … `抽奖`→宝くじ→**抽選**、`秒杀`→スパイク→**タイムセール**、
  `核销`→償却→**検証**、`可用`→使用済み→**利用可能**、`清除成功`→明確な成功→**消去しました**
- **英語のまま残っていた語** … `兑换`→GO→**交換**、`天/时/分/秒`→D/H/M/S→**日/時/分/秒**、
  `划线价`→ORP→**参考価格**、`付费会员`→SVIP→**有料会員**
- **表記ゆれの統一** … `微信`→**WeChat**。同一の中国語原文に複数コードが割り当てられ
  訳文が食い違っていた 19 件（`参数错误`、`支付成功`、`登录失败` など）を統一

残りは機械翻訳のままです。訳語を直す場合は
**管理画面「設定 → 多言語設定 → 言語コード」から編集**し、同じ文言を `ja_jp.php` にも反映してください。

## 管理画面（template/admin）

- `src/i18n/lang/ja.js` ほかに `ja` ロケールを追加し、`src/i18n/index.js` に登録済み
- ヘッダー右上に **言語切替（中 / EN / 日）** を追加（`layout/navBars/breadcrumb/user.vue`）。
  従来 `onLanguageChange()` は実装されているのに UI が無く、到達不能でした
- `src/libs/request.js` が選択中の言語を `Cb-lang` ヘッダーで送るようになり、
  サーバー側のメッセージ（約 1,300 件）が管理画面の言語に追従します

## 既知の制限

**管理画面の画面内テキストはほぼ中国語のハードコードのままです。**
`src/i18n/` がカバーするのはルーター名・レイアウト設定・ログイン画面などの一部で、
`src/` 配下には約 8,000 の中国語文言が 540 ファイルに直接埋め込まれています。
全面的な日本語化には、それらを `$t()` 呼び出しへ置き換える大規模なリファクタが必要です。

**左ナビのメニュー名も未対応です。**
メニューは `eb_system_menus.menu_name`（中国語）をそのまま返しており
（`app/services/system/SystemMenusServices.php` の `tidyMenuTier()`）、翻訳層を通っていません。
対応するには `$menu['title'] = lang($menu['menu_name'])` に変更したうえで、
823 件のメニュー名を言語パックへ追加する必要があります（現状の重複は 33 件のみ）。
