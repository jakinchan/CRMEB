# クラウド事業者の比較と費用試算（日本 / カナダ / 中国）

案A（国別に独立した CRMEB を3インスタンス）を前提とした、クラウド事業者の選定資料です。

> ⚠️ **価格について**
> この資料の金額は**発注用の見積りではなく、規模感を掴むための試算レンジ**です。
> 作成時にライブ価格の取得を試みましたが環境の制約で実行できず、数値は学習データ
> （2026年5月時点）に基づく概算です。**必ず各社の公式料金計算ツールで再確認してください。**
> 一方、次章の「技術要件」と「対応可否」はこのリポジトリの実装を直接確認した事実です。

---

## 1. このアプリの技術要件（実装から確定）

事業者選定を左右する要件を、コードベースから洗い出したものです。

| 要件 | 内容 | 根拠 |
| --- | --- | --- |
| PHP | 7.4（同梱 Docker イメージ）。`composer.json` は `>=7.1`。PHP 8.2 でも構文解析は通る | `help/docker/docker-compose.yml`, `crmeb/composer.json` |
| 必須拡張 | json, curl, bcmath, mbstring, zip, simplexml | `composer.json` |
| MySQL | 8.0 | 同梱イメージ `mysql:v8.0.45` |
| Redis | 必須。キューの既定ドライバが `redis` | `crmeb/config/queue.php` |
| **常駐プロセス** | workerman が **40001 / 40002 / 40003** で待ち受け。加えてキューワーカーとタイマー常駐 | `crmeb/config/workerman.php`, `runtime/timer.pid` |
| WebSocket | Nginx から `/notice` `/msg` を上記ポートへプロキシ | `help/docker/nginx/vhost.conf` |
| **オブジェクトストレージ** | `local` / 七牛 / **阿里云OSS** / **腾讯云COS** / 京东 / 华为OBS / 天翼 の7種のみ | `crmeb/config/upload.php` |

### ここが効く2点

**① サーバーレス・共有ホスティングは使えません。**
workerman の常駐プロセスとキューワーカーが必要なため、**VM またはコンテナ（常時起動）**が前提です。
Lambda / Cloud Functions / Cloud Run（リクエスト駆動）や、デーモンを立てられない共有レンタルサーバーは不可です。

**② AWS S3 / Google Cloud Storage / Azure Blob には対応していません。**
`upload.php` の `stores` に S3 系ドライバがありません。AWS や GCP を選ぶ場合、次のいずれかになります。

- `local`（サーバーのディスク）に保存する — 小規模なら可。ただし複数台構成やコンテナ再作成でファイルが消える
- **S3 ドライバを実装する** — 要開発
- 画像だけ阿里云OSS / 腾讯云COS を併用する — 事業者を跨ぐ構成になる

**阿里云OSS と 腾讯云COS は海外リージョン（東京・トロント等）も持っている**ため、
これらを選べば追加開発なしで海外拠点でもオブジェクトストレージが使えます。

## 2. 事業者の対応可否（価格以外の決定要因）

3か国すべてを1社でまとめられるかが最大の分かれ目です。

| 事業者 | 日本 | カナダ | 中国本土 | CRMEB ストレージ対応 | 総合 |
| --- | --- | --- | --- | --- | --- |
| **腾讯云 Tencent Cloud** | ○ 東京 | ○ トロント | ○ 本土多数 | ✅ `cos` ネイティブ | **◎ 1社で3か国+ストレージ対応** |
| **阿里云 Alibaba Cloud** | ○ 東京 | △ región無し（米国から配信） | ○ 本土多数 | ✅ `oss` ネイティブ | ○ カナダが弱い |
| **AWS** | ○ 東京/大阪 | ○ ca-central-1 | △ 別法人・別アカウント | ❌ S3ドライバ無し | △ 中国と storage に難 |
| **Google Cloud** | ○ 東京/大阪 | ○ モントリオール | ✕ リージョン無し | ❌ GCSドライバ無し | ✕ 中国不可 |
| **Azure** | ○ 東日本 | ○ Canada Central | △ 21Vianet 運営 | ❌ Blobドライバ無し | △ |
| **さくら / ConoHa 等（国内）** | ○ | ✕ | ✕ | ❌（`local` 運用） | 日本単独なら安価 |

> リージョンの有無は各社の公開情報に基づく認識です。**発注前に最新のリージョン一覧で確認してください。**
> 特に阿里云のカナダリージョンの有無は変わりうるため要確認です。

### 中国本土の規制（ここは費用より重い制約）

- **ICP 備案が必須**です。未取得だと接続が不安定・遮断されます
- 備案には**中国国内の事業実体（法人）と、中国本土リージョンのサーバー**が必要
- 取得には数週間〜数か月かかります
- 香港リージョンは備案不要ですが、本土からのアクセス速度と安定性は落ちます

**中国は「安い事業者を選ぶ」問題ではなく「備案を通せるか」の問題**です。ここが最初のボトルネックになります。

## 3. 推奨構成とサイジング

CRMEB は PHP-FPM + MySQL + Redis + 常駐ワーカーの構成です。以下は1インスタンス（1か国）あたりです。

### 構成A：最小（検証・小規模ローンチ）

VM 1台に全部同居。Docker Compose をそのまま使えます。

| リソース | 仕様 |
| --- | --- |
| VM | 2 vCPU / 4 GB RAM / SSD 80 GB |
| MySQL | 同一VM上（Docker） |
| Redis | 同一VM上（Docker） |
| ストレージ | `local` または OSS/COS |

### 構成B：標準（本番・推奨）

DBを分離して運用性を上げます。

| リソース | 仕様 |
| --- | --- |
| VM（アプリ） | 2〜4 vCPU / 8 GB RAM / SSD 100 GB |
| マネージドMySQL | 2 vCPU / 4 GB / 100 GB |
| マネージドRedis | 1 GB |
| オブジェクトストレージ | 100 GB + 転送量 |
| CDN | 画像配信（任意） |
| ロードバランサ | 任意（1台構成なら不要） |

### 構成C：冗長（トラフィック増加後）

アプリVM 2台 + LB、MySQL をリードレプリカ付きに。
**ただし複数台にする場合、`local` ストレージは使えません**（アップロード画像が片方にしか無い状態になる）。
OSS/COS への移行が前提になります。

## 5. 推奨

### 第1候補：腾讯云（Tencent Cloud）で3か国を統一

**理由**

1. **東京・トロント・中国本土すべてにリージョンがある**（要確認）ため、1社・1つの管理画面で3インスタンスを運用できる
2. **`cos` ドライバが CRMEB にネイティブ実装済み**で、オブジェクトストレージに追加開発が不要
3. 中国本土の備案フローが整備されている
4. 国際SMS（腾讯云）も CRMEB に実装済みで、今回追加した国際SMS設定がそのまま使える

**懸念**：日本国内での日本語サポートや請求周りは AWS ほど手厚くない可能性があります。ここは商談で確認してください。

### 第2候補：日本・カナダは AWS、中国は 阿里云 or 腾讯云

**理由**：日本・カナダのサポートと信頼性を優先する構成です。

**条件**：AWS 側は `local` ストレージで始めるか、**S3ドライバの実装が必要**です。
1台構成なら `local` で運用できますが、将来の冗長化時に必ず詰まります。
早めに S3 ドライバを実装するか、画像だけ COS/OSS を使う判断が必要です。

### 避けたい選択

**Google Cloud で3か国** は、中国本土リージョンが無いため成立しません。

## 6. 決める順番の提案

費用比較より先に決めるべきことがあります。

1. **中国本土で ICP 備案を通せるか** — 中国国内の法人実体が必要。不可なら中国向けは香港リージョン運用か、中国展開自体の再検討
2. **日本・カナダの決済手段** — Stripe/PayPal 実装の工数を見込むか、線下・残高払いで開始するか
3. **オブジェクトストレージをどうするか** — `local` で始めるか、OSS/COS を使うか、S3ドライバを実装するか
4. **1社統一か、地域ごとに最適な事業者か** — 運用工数 vs サポート品質のトレードオフ
5. → ここまで決まってから、該当構成の**実価格を各社の計算ツールで取得**して比較
