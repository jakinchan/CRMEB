# WeChat ミニプログラム リリース手順

`docs/test-env-wechat-miniprogram.md` は「自宅PC + Docker + Cloudflare Tunnel」構成での
**动作確認（开发版・体验版まで）**の手順でした。本ドキュメントは、その先の
**正式リリース（审核提出〜公開）**に必要な手順・要件をまとめたものです。

---

## 0. 前提: 正式リリースには ICP 備案済みドメインが必須

`docs/test-env-wechat-miniprogram.md` の冒頭でも触れたとおり、WeChat ミニプログラムの
「服务器域名」ホワイトリスト登録には **ICP 備案済みドメイン**が要求されます。
自宅PC + Cloudflare の一時ドメイン、香港ホスティング（`china-access-via-hongkong.md`
参照）のいずれでも登録できません。

**したがって本ドキュメントの手順は、ICP 備案済みドメインへの移行が完了して
初めて実行可能**です。備案が未完了の間は「4. 本番ドメインへの切り替え」より前の
準備作業（アカウント・アセット・コードの準備）のみ進めておくことができます。

| 段階 | 必要なもの | このドキュメントでの位置付け |
| --- | --- | --- |
| 开发版・体验版での動作確認 | 自宅PC Docker + Cloudflare Tunnel | `test-env-wechat-miniprogram.md` |
| **正式リリース** | **ICP備案済みドメイン + 本番サーバー** | 本ドキュメント |

---

## 1. アカウントの準備

### 1-1. 微信公众平台でのミニプログラム登録

[https://mp.weixin.qq.com](https://mp.weixin.qq.com) で登録します。

| アカウント種別 | 決済(微信支付) | 備考 |
| --- | --- | --- |
| 個人 | ✕ 使えない | 表示・会員登録動線のみのテストなら可 |
| **企業（企业）** | ○ 使える | **正式リリースするなら実質必須** |

個人アカウントで登録済みの場合、企業への切り替え（主体变更）は別途手続きが必要です。
正式リリースを見据えるなら、最初から企業アカウントで登録してください。

### 1-2. 開発者情報の取得

微信公众平台「開発 → 開発設定（开发设置）」で以下を取得します。

| 項目 | 用途 |
| --- | --- |
| AppID | `template/uni-app/manifest.json` の `mp-weixin.appid`、CRMEB管理画面の `routine_appId` |
| AppSecret | CRMEB管理画面の `routine_appsecret` |

現在リポジトリの `manifest.json` には CRMEB のデモ用 AppID（`wx3b82801238ca1b57`）が
入ったままです。**必ず取得した自分の AppID に差し替えてください**
（[manifest.json:186](../template/uni-app/manifest.json:186)）。

### 1-3. 微信支付の申請（決済を使う場合）

企業アカウントで「微信支付」の開通申請を行います。営業許可証・銀行口座情報などの
審査があり、申請から開通まで数営業日かかります。決済機能を使わない
（表示・会員登録のみの）ミニプログラムであれば不要です。

## 2. サーバー側の準備（本番ドメイン）

### 2-1. ICP 備案の完了

中国本土の事業実体でのICP備案が前提です。個人での代行取得は規約上できません。
備案の具体的な進め方は本ドキュメントの範囲外です（行政書士的な代行サービスや
クラウド事業者の備案サポートを利用するのが一般的です）。

### 2-2. サーバーの移行

備案済みドメインに対応するサーバー環境へ移行します。`cloud-provider-comparison.md`
`multi-country-deployment.md` を参照してください。自宅PC + Cloudflare Tunnel の
構成は**正式リリースでは使えません**（一時的なテスト用途に限る）。

### 2-3. CRMEB 側の設定を本番ドメインへ更新

| 設定箇所 | 値 |
| --- | --- |
| 管理画面「設定 → 基本設定」の `site_url` | `https://（備案済みドメイン）` |
| `template/uni-app/config/app.js` の `HTTP_REQUEST_URL`（`#ifdef MP \|\| APP-PLUS` 側） | 同上 |

`site_url` は `crmeb/public/mobile.html` のiframe埋め込みだけでなく、
商品画像・テーマ画像など**DBに保存された絶対URLの基点**にもなります。
ドメインを切り替えた際は、DB内に旧ドメイン（`http://localhost:8080` など）が
残っていないか確認してください。

```sql
-- 例: 旧ドメインの残存確認（見つかった場合は個別に置換が必要）
SELECT TABLE_NAME, COLUMN_NAME FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'crmeb' AND DATA_TYPE IN ('varchar','text','longtext')
  -- 実際の検索は各カラムに対して LIKE '%旧ドメイン%' を実行
```

### 2-4. 服务器域名（ドメインホワイトリスト）の登録

微信公众平台「開発 → 開発設定 → 服务器域名」で、備案済み本番ドメインを登録します。

| 設定項目 | 用途 |
| --- | --- |
| request合法域名 | 通常のAPIリクエスト（`HTTP_REQUEST_URL`） |
| socket合法域名 | WebSocket（`/notice` `/msg`、workerman） |
| uploadFile合法域名 | 画像アップロード |
| downloadFile合法域名 | 画像・ファイルダウンロード |

登録できるのは HTTPS のみで、**1か月に5回まで**という変更回数制限があります。
テスト中に何度も変えると足りなくなるため、本番ドメインが確定してから登録してください。

登録が完了したら `manifest.json` の `mp-weixin.setting.urlCheck` を
**`true` に戻してください**（テスト用に `false` にしていた場合）。
正式版は `urlCheck` の設定に関わらずドメイン検証が必須ですが、`true` にしておくことで
開発者ツール上でも本番相当の検証がかかり、リリース前に気付けます。

## 3. ビルド

### 3-1. HBuilderX でのビルド

`template/uni-app/package.json` にビルドスクリプトが無く、**HBuilderX（DCloud純正の
GUI IDE）でのビルドが前提**です（詳細は `docs/overseas-members.md` の
「H5サイトのビルドと配信の仕組み」、および `test-env-wechat-miniprogram.md` 4-1 参照）。

1. HBuilderX で「ファイル → インポート → 既存プロジェクト」から `template/uni-app` を開く
2. `manifest.json` の AppID が自分のものになっているか再確認
3. 「発行 → 微信小程序」を選択
4. 出力先: `unpackage/dist/build/mp-weixin/`

### 3-2. 微信開発者ツールでの最終確認

1. 微信開発者ツールで `unpackage/dist/build/mp-weixin` を開く
2. 「詳細 → ローカル設定」の**「合法域名のチェックを行わない」のチェックを外す**
   （本番相当の検証を通す。テスト時はここにチェックを入れていたはず）
3. コンパイルし、ドメインエラーが出ないこと（＝服务器域名の登録が正しいこと）を確認
4. `test-env-wechat-miniprogram.md` の確認項目（トップページ表示・会員登録・
   画像表示・言語切替・通知チャット）を本番ドメインに対して再実施

## 4. アップロードと審査提出

### 4-1. コードのアップロード

微信開発者ツールで「アップロード」をクリックし、バージョン番号（例: `1.0.0`）と
バージョン説明を入力してアップロードします。

### 4-2. 体验版での最終確認（推奨）

アップロード後、微信公众平台「管理 → バージョン管理」で該当バージョンを
**「体验版に設定」**し、「メンバー管理」で社内テスターを体験メンバーに追加します。
審査に出す前に、本番ドメイン・本番データでの動作を実機で最終確認してください。

### 4-3. 審査提出（提交审核）

微信公众平台「管理 → バージョン管理」から「提交审核」を行います。

審査時に入力する主な項目:

| 項目 | 内容 |
| --- | --- |
| カテゴリ（服务类目） | 業種に応じて選択（例: 電子商取引 → ネットショップ）。カテゴリによって
  追加の资质（許可証等）提出が必要になる場合があります |
| 画面のプレビュー | 主要画面のスクリーンショット |
| テスト用アカウント | 審査担当者がログインして確認できるテストアカウント |
| バージョン説明 | 今回の変更点 |

審査には通常 **1〜7営業日**かかります（カテゴリや混雑状況により変動）。

### 4-4. よくある却下理由

| 理由 | 対応 |
| --- | --- |
| カテゴリと实际機能の不一致 | カテゴリを機能に合わせて選び直す |
| 決済関連の資質不足 | 微信支付の商户認証・业务类目を確認 |
| テストアカウントでログインできない | 審査担当者が実際に動作確認できることを事前に検証 |
| プライバシーポリシー・ユーザー協議の不備 | `pages/users/privacy/index` の内容を確認（[login/index.vue](../template/uni-app/pages/users/login/index.vue:109) から遷移） |
| 個人情報の取扱いに関する説明不足 | 小程序の「隐私保护指引」設定（公众平台側の別画面）を確認 |

却下された場合は理由に対応した上で再度「提交审核」します。

### 4-5. 正式発布（发布）

審査通過後、微信公众平台「管理 → バージョン管理」で「发布」を実行すると
一般公開されます。**発布は審査通過後に手動で行う操作**で、通過しても自動公開はされません。

## 5. リリース後の運用

### 5-1. バージョン更新の流れ

コード変更のたびに 3〜4 を繰り返します（ビルド → アップロード → 体验版確認 → 提交审核 → 发布）。
`manifest.json` の `versionName` / `versionCode`（[manifest.json:5-6](../template/uni-app/manifest.json:5)）を
更新時に上げる運用にしておくと、公众平台側のバージョン管理と対応が取りやすくなります。

### 5-2. 服务器域名の変更が必要になったら

前述のとおり月5回までの制限があります。ドメイン移行（例: ホスティング事業者の変更）を
予定している場合は、余裕を持ってスケジュールしてください。

### 5-3. 監視

- 微信公众平台「統計」でアクセス状況・クラッシュ状況を確認できます
- サーバー側は `help/docker/` 構成であれば `docker compose logs` / `supervisorctl status`
  （`test-env-wechat-miniprogram.md` 5章）で稼働確認します

## 6. 本ドキュメントで到達できないこと

| 項目 | 状況 |
| --- | --- |
| ICP備案の代行取得 | 対象外（行政手続きのため） |
| 微信支付の商户審査 | 対象外（金融機関・微信側の審査プロセス） |
| カテゴリ別の资质提出 | 業種依存のため個別に公众平台の案内に従う |

> 本ドキュメントのうち CRMEB / uni-app の設定に関する記述はリポジトリの実装を
> 直接確認したものです。一方、微信公众平台の画面構成・審査基準・服务器域名の
> 変更回数制限などは変更されることがあるため、実施時に公众平台の最新の案内を
> 必ず確認してください。
