# 香港ホスティングで中国からアクセスする構成（ICP備案なし）

中国向けサイトを **香港リージョン**に置くことで、**ICP備案を取得せずに**中国本土から
アクセスできる構成にします。

## なぜ備案が不要なのか

ICP備案（ICP备案）は **中国本土に設置されたサーバー**でウェブサイトを公開する事業者に
課される許可制度です。香港は本土とは別の管轄として扱われるため、香港・シンガポール・
東京などに置く限り備案の対象外です。

これは抜け道ではなく、中国国外の事業者が中国の顧客に販売する際の**標準的な構成**です。

> ⚠️ ただし「備案が不要」＝「快適に繋がる」ではありません。
> 本土からのアクセスは国際回線を経由するため、**速度と安定性が本土ホスティングに劣ります**。
> ここが最大のトレードオフで、後述の対策で緩和はできますが解消はできません。

---

## 1. 構成

案A（国別インスタンス）の「中国向けインスタンス」を香港に置く形です。

| 項目 | 設定 |
| --- | --- |
| リージョン | 香港（腾讯云 `ap-hongkong` / 阿里云 `cn-hongkong`） |
| ドメイン | `.com` / `.hk` など。**`.cn` は避ける**（実名認証と本土運用が絡む） |
| 既定言語 | 简体中文（`eb_lang_type.is_default` = id 1） |
| オブジェクトストレージ | 腾讯云COS または 阿里云OSS の**香港バケット**（備案不要） |
| SMS | 阿里云 / 腾讯云 の**国際SMS**で `+86` 宛に送信 |
| DB / Redis | 同一リージョン内に配置（越境させると致命的に遅くなる） |

**DBを本土や日本に置いてアプリだけ香港、という構成は避けてください。** クエリごとに
国際回線を往復するため、体感速度が壊滅的に落ちます。1リージョンに寄せるのが原則です。

---

## 2. 速度・安定性への対策（備案が不要な範囲で）

### 効果が高い順

| 対策 | 効果 | 備案 |
| --- | --- | --- |
| **香港リージョンを選ぶ**（東京・米国より本土に近い） | 中 | 不要 |
| **画像・CSS・JSをオブジェクトストレージ＋海外CDNへ** | 大 | 不要 |
| **画像の軽量化**（WebP化、サイズ最適化） | 大 | 不要 |
| **HTTP/2 + gzip/brotli、キャッシュヘッダの適正化** | 中 | 不要 |
| **API応答の削減**（リクエスト数を減らす） | 中 | 不要 |
| 中国本土ノードを持つCDN | 特大 | **必要** ← 使えない |

**ページ表示時間の大半は画像などの静的ファイル**です。ここを海外CDN（腾讯云/阿里云の
グローバルCDN、Cloudflare 等）に載せるだけで体感が大きく変わります。CRMEB は
`config/upload.php` の `cos` / `oss` ドライバに対応済みなので、追加開発は不要です。

### 正直な限界

**中国本土ノードを使うCDN製品はほぼ例外なくICP備案が前提**です
（Cloudflare China Network、阿里云CDN中国大陸ノード、腾讯云CDN中国境内 など）。
つまり「一番効く対策」は備案なしでは使えません。

香港構成で現実的に狙えるのは「実用的に使える速度」までで、
本土ホスティング並みの体験は得られない、と割り切る必要があります。

---

## 3. 決済：ここが最大の実装課題

香港構成でも中国の顧客から決済を受けたい場合、**同梱コードのままでは制約があります。**

### 通貨が CNY にハードコードされている

[PayClient.php:165](crmeb/crmeb/services/easywechat/v3pay/PayClient.php:165) と
[:393](crmeb/crmeb/services/easywechat/v3pay/PayClient.php:393) で
`'currency' => 'CNY'` が固定値で埋め込まれています。通貨を切り替える設定はありません。

### 2つのパターン

| パターン | 加盟店 | 決済通貨 | 同梱コードで動くか |
| --- | --- | --- | --- |
| **A: 中国本土の法人で微信支付/支付宝の加盟店契約** | 本土法人 | CNY | ✅ **そのまま動く** |
| **B: 海外法人で跨境（クロスボーダー）契約** | 香港/海外法人 | 外貨建て | ⚠️ **要改修**（`currency` の外部化） |

**パターンAが圧倒的に楽です。** サーバーは香港（備案不要）、決済は本土加盟店という
組み合わせは可能で、コード改修が不要です。本土法人をお持ちなら第一候補です。

パターンBは跨境決済の仕様に合わせて `currency` を設定可能にする改修が必要です。
改修自体は小さい（`PayClient.php` の2箇所を設定値化）ですが、
跨境契約は審査があり、**「審査不要」というご要望とは相反します**。

### 決済を諦める場合の代替

- **線下支払い（銀行振込）** — 改修不要。管理画面で有効化するだけ
- **残高（余额）払い** — 事前チャージ運用。改修不要

## 4. SMS・メール（備案不要で動く）

| 用途 | 手段 | 備考 |
| --- | --- | --- |
| 認証コード（SMS） | 阿里云 / 腾讯云 の**国際SMS**で `+86` 宛に送信 | 今回追加した `config/sms.php` の `international` 設定で対応済み |
| 認証コード（メール） | SMTP（Amazon SES 等） | `config/mail.php`。**中国国内でのメール到達率は不安定**なので主手段にはしない |

**中国向けはSMS認証を主軸に**してください。中国の利用者はメールをあまり使わず、
かつ海外SMTPからのメールは本土のプロバイダで弾かれやすいです。

なお国際SMSで `+86` 宛に送る場合、**中国の受信側規制で到達率が落ちることがあります**。
本土の加盟店・本土のSMS業者を使えるならその方が確実です。

## 5. 微信（WeChat）連携の制約

CRMEB は公众号・ミニプログラム連携が中核機能ですが、ここは備案が絡みます。

| 機能 | 香港構成で使えるか |
| --- | --- |
| H5（ブラウザ）での閲覧・購入 | ✅ 使える |
| 公众号の連携 | ⚠️ 公众号自体の登録に中国の主体が必要。JSサドメイン設定も要審査 |
| **ミニプログラム** | ❌ **サーバードメインのホワイトリスト登録が必要で、実質備案済みドメインが前提** |
| 微信内ブラウザでの決済（JSAPI） | ⚠️ 支付授权目录の設定が必要 |

**ミニプログラムは香港構成では実質使えません。** 中国向けを H5（微信内ブラウザ含む）に
絞る前提で設計してください。CRMEB は uni-app で H5 ビルドできるので機能面は成立します。

## 6. 構築手順（差分のみ）

基本手順は [multi-country-deployment.md](multi-country-deployment.md) と同じです。
中国向けインスタンスで追加・変更する点だけ挙げます。

1. **リージョンを香港にする** — VM / MySQL / Redis / ストレージをすべて `ap-hongkong` 等に揃える
2. **ドメインは `.com` / `.hk`** を使い、`.cn` は取らない
3. **既定言語を简体中文にする**
   ```sql
   UPDATE eb_lang_type SET is_default = 0;
   UPDATE eb_lang_type SET is_default = 1 WHERE id = 1;
   ```
   適用後に `find crmeb/runtime/cache -type f -name "*.php" -delete` でキャッシュクリア
4. **オブジェクトストレージを香港バケットに向ける** — 管理画面の「設定 → ストレージ」で
   `cos` または `oss` を選び、香港リージョンのバケットを指定
5. **海外CDNを静的ファイルに被せる**
6. **SMSを国際SMS対応の業者（阿里云/腾讯云）に切替** — `config/sms.php` の `international` を設定
7. **決済** — 本土加盟店が使えるならそのまま。使えないなら線下・残高で開始
8. **タイムゾーンを `Asia/Shanghai`** に（`.env` の `DEFAULT_TIMEZONE`）

## 7. この構成の評価

| 観点 | 評価 |
| --- | --- |
| ICP備案 | ✅ **不要**。これがご要望の主目的で、確実に満たせます |
| 構築の速さ | ✅ 備案の数週間〜数か月の待ちが無くなる |
| 表示速度 | ⚠️ 本土ホスティングに劣る。静的ファイルのCDN化で緩和 |
| 安定性 | ⚠️ 国際回線に依存。時間帯によって変動する |
| 決済 | ⚠️ 本土加盟店があれば無改修。無ければ改修または線下運用 |
| ミニプログラム | ❌ 使えない。H5に絞る |
| コード改修 | ✅ **基本的に不要**（跨境決済を使う場合のみ `currency` の外部化） |

**「まず中国市場を試す」段階には適した構成**です。手応えがあってから本土ホスティング＋
備案に移行する、という段階的な進め方が現実的です。

移行時はDBを本土リージョンに移すだけで済むよう、**最初から `local` ストレージではなく
OSS/COS を使っておく**ことを勧めます。画像がサーバーローカルにあると移行時に厄介になります。

## 8. 確認が必要な点

本資料の技術的記述はこのリポジトリの実装を直接確認したものですが、
以下は各社の最新情報と契約条件を確認してください。

- 香港リージョンの提供状況と料金（腾讯云 `ap-hongkong` / 阿里云 `cn-hongkong`）
- 国際SMSの `+86` 宛の到達率と料金
- 微信支付・支付宝の加盟店契約条件（本土法人が必要か、跨境が使えるか）
- 中国向けCDNで備案不要のまま使える製品の有無（変わりうる領域です）

また ICP備案の要否や中国の規制運用は変更されることがあります。
事業判断の前に、現地の専門家または各クラウド事業者に確認されることをお勧めします。
