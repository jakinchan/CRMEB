# HBuilderX CLI 実機検証手順（WeChatミニプログラム自動ビルドの調査）

[minipc-cloudflare-production-release.md](minipc-cloudflare-production-release.md) の4章で
「フェーズ2・要検証」としたHBuilderX CLIによるミニプログラム自動ビルドについて、
自宅PC（実際にHBuilderXがインストールされている環境）で検証するための手順です。

## 0. この文書の位置づけ

DCloud公式のCLIドキュメント（`https://hx.dcloud.net.cn/CLI/README`）を確認しようとしましたが、
作業時点でWeb検索・フェッチツールがエラーで利用できず、**正確な公式コマンド構文を確認できていません**。
記憶に頼った構文を「手順」として提示すると誤った情報を事実であるかのように伝えるリスクがあるため、
ここでは**実機で安全に調査するための手順**を提供します。見つかった内容は下部の「調査結果テンプレート」に
記録し、共有してください。それをもとに`build-miniprogram.ps1`の`Invoke-HBuilderXCliBuild`関数を
実装します。

## 1. 準備

- `check-env.ps1`の実行で、HBuilderXは `C:\Program Files\HBuilderX\HBuilderX.exe` に
  インストール済みであることを確認済みです。
- 作業前に、既存の`unpackage/`ディレクトリなど検証で変化しうるものは影響が小さいので
  バックアップ不要です（gitignore対象、かつビルド成果物のため再生成可能）。

## 2. Step 1: インストールディレクトリの中身を調べる

CLIツールが同梱されているか、フォルダ構成から確認します。

```powershell
Get-ChildItem "C:\Program Files\HBuilderX" -Recurse -Depth 1 |
    Where-Object { $_.Name -match "cli" } |
    Select-Object FullName
```

`cli`という名前を含むファイル・フォルダ（例: `cli.js`, `cli.bat`, `cli`フォルダ）が
見つかるか確認してください。見つかった場合は、そのファイルパスを記録します。

## 3. Step 2: 公式ドキュメントをブラウザで確認する

以下のURLをブラウザで開き、正確なコマンド構文・前提条件（ログイン要否、対応バージョン等）を
確認してください。

- `https://hx.dcloud.net.cn/CLI/README`
- 見つからない場合は「HBuilderX 命令行」「HBuilderX CLI」で検索

ページの内容（特にコマンド例のコードブロック）をそのままコピーしておいてください。

## 4. Step 3: ヘルプ表示を安全に試す

見つかったCLIエントリポイント（例: `cli.bat`, `cli.js`など。Step 1/2の結果に応じて置き換え）に対し、
まずは副作用のない`-h` / `--help` / `-v`系のオプションだけを試します。

```powershell
# 例（実際のファイル名・場所はStep 1/2の結果に置き換える）
& "C:\Program Files\HBuilderX\cli.bat" -h
# または
node "C:\Program Files\HBuilderX\cli\cli.js" --help
```

**いきなり`publish`や`build`系のコマンドは実行しないでください。** まずヘルプで
サブコマンド一覧・必須オプションを確認してから進めます。

## 5. Step 4: DCloudアカウントのログイン要否を確認する

1. HBuilderXをGUIで一度起動し、DCloudアカウントでログイン済みかを確認する
2. 未ログインの状態でStep 3のCLIコマンドを実行し、ログインを要求するエラーが出るか確認する
3. ログインが必要な場合、そのログイン状態がCLI実行時にも引き継がれるか（ヘッドレス実行時に
   毎回ログインを要求されないか）を確認する

## 6. Step 5: プロジェクトを開く・ビルドする最小コマンドを試す

Step 2で確認した公式構文に従い、`template/uni-app`を対象に**最小限の**動作確認を行います。
（例: プロジェクトを開くだけのコマンド → 成功すれば次にmp-weixin向けのビルド/発行コマンド）

実行結果（成功したコマンドの正確な文字列と、生成された成果物のパス）を記録してください。

## 7. Step 6: 非対話セッションでの動作確認（自動化の可否を左右する最重要ポイント）

CLIコマンド自体が動いても、**GUIアプリケーションであるHBuilderXの自動化は、
対話的なデスクトップセッションを必要とする可能性が高い**です。Windowsのタスクスケジューラで
「ユーザーがログオンしているかどうかにかかわらず実行する」設定にした場合、GUIアプリは
非表示のSession 0で起動を試みて失敗することがよくあります。

以下の2パターンで同じコマンドを試し、結果を比較してください。

| 実行方法 | 期待される用途 |
| --- | --- |
| 手動でPowerShellを開いて実行（通常のログインセッション） | 動くかどうかのベースライン確認 |
| タスクスケジューラで「ログオンしているかどうかにかかわらず実行する」に設定して実行 | `deploy.ps1`的な自動化フローに組み込めるかの判定 |

後者が失敗する場合、選択肢は次のいずれかになります。

- タスクスケジューラを「ユーザーがログオンしているときのみ実行する」設定に変更し、
  自宅PCを常時ログイン状態にしておく（セキュリティ上のトレードオフに注意）
- 自動化を諦め、[test-env-wechat-miniprogram.md](test-env-wechat-miniprogram.md)の手順通り
  手動ビルドを継続する

## 9. 次のステップ

- 調査結果が「自動化可能」なら、その内容を伝えてください。`build-miniprogram.ps1`の
  `Invoke-HBuilderXCliBuild`関数に実際のコマンドを実装します。
- 「自動化不可」の場合、[minipc-cloudflare-production-release.md](minipc-cloudflare-production-release.md)の
  フェーズ2を「見送り・手動継続」として確定させ、この文書はその判断根拠として残します。
- Web検索ツールが復旧した場合は、Step 2の公式ドキュメント確認をこちら側でも代行できます。
